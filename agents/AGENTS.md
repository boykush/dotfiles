# グローバル設定

Claude Code / Codex 共通の個人ルール（`~/.claude/CLAUDE.md` と `~/.codex/AGENTS.md` の実体。dotfiles で管理）。

## 私のナレッジ（Scraps wiki）を引く

`scraps` MCP サーバーは私が書き溜めた個人 wiki（`boykush/wiki`）で、私の1次ソース。全セッションから同じサーバーを見る。**私の過去の判断とすれ違った答えを出さないため**に引くのであって、話す前に毎回参照するためのものではない。次の2通りで引く。

**明示的に探すとき** —「こういうことが書いてある記事なかったっけ」「あれ何だっけ」のように、私が心当たりを頼りに聞くケース。私も題名を覚えていないので言い回しは曖昧になる。`search_scraps` を語を変えて何度か試す（`logic: "or"` で広げてから絞る）。それでも無ければ「wiki にない」と明示する。私の記憶違いなのか、まだ書いていないだけなのかの切り分けになるため。

**よしなに引くとき** — 頼まれずに引くのは、**私の過去の判断・命名・方針を踏まえるかどうかで答えが変わる**ときだけ。私の文脈に閉じた語（プロジェクト名・略語・個人的な命名）が出たというだけでは引かない。その語の指示対象が分からないまま進むと話が噛み合わない、というところまで来て初めて引く。迷ったら引かない側に倒す。空振りは黙って流してよい（毎回「wiki にはありませんでした」と報告されると会話が途切れる）が、黙っても私の待ち時間は消えないので、当たる見込みが薄いなら最初から引かない。

引かなくてよい例。ここまで引くと過剰:

- 一般的な技術語（言語・OSS・プロトコル・設計用語）。wiki の有無で答えが変わらない
- 目の前のコード・設定を読めば分かること。コードが正なので wiki を経由する意味がない
- 実装・デバッグ・レビューで手が動いている最中に出てくる固有名詞。ほぼリポジトリ側の語
- 同じ話題で一度引いた後。同一セッション中に引き直さない

引き方と扱い:

- 手順は `search_scraps` → 当たりを `get_scrap` で読む → 関連を辿るなら `lookup_scrap_links` / `lookup_scrap_backlinks`。私が何を蓄えているかの地図が要るときは `list_tags`、タグ起点で並べるなら `lookup_tag_backlinks`。
- wiki の内容に乗って話すときは `[[Title]]`（ctx 付きなら `[[Ctx/Title]]`）を添える。どの scrap の話をしているか私と揃えるため。
- wiki は私の理解のスナップショットで、リポジトリの現状ではない。食い違ったらコードを正とし、食い違ったこと自体を報告する。
- MCP が繋がっていないセッションでは、wiki 本体が `~/dotfiles/wiki/scraps` 配下に markdown で置いてあるので Grep / Read で代用する。

## コードコメント

- 連続する1つのコメントブロックは**最大5行**。コード・設定ファイル・スクリプトを問わず一律で適用する。
- 5行に収まらないなら、コメントを削るかコード側を分かりやすくする。長い背景説明は README / ADR / PR 本文に書く。
- 「何をしているか」ではなく「なぜそうしたか」だけ書く。コードを読めば分かることは書かない。
- 差分の説明（`// 〜を追加`、`// 修正: 〜`）は書かない。それは commit message と PR の仕事。
- 既存のコメントは、その箇所自体を編集するとき以外は短縮しない。
