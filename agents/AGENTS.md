# グローバル設定

Claude Code / Codex 共通の個人ルール（`~/.claude/CLAUDE.md` と `~/.codex/AGENTS.md` の実体。dotfiles で管理）。

## 個人ナレッジの参照（Scraps wiki）

私の1次ソースは `scraps` MCP サーバー（実体は個人 wiki `boykush/wiki`。全セッションから同じサーバーを見る）。私の文脈に閉じた固有名詞が出てきたら、推測やこちらへの質問より先にここを引く。何を指しているかの認識をまず合わせるため。

- 引くのは**指示対象が私の側にしかない語**に限る。プロジェクト名・サービス名・略語・個人的な命名・過去の決定など、リポジトリのコードや一般知識だけでは指示対象が確定しないもの。OSS 名や一般用語は引かない。
- 手順は `search_scraps`（語が揺れそうなら `logic: "or"` で広めに）→ 当たりを `get_scrap` で読む → 関連が要るときだけ `lookup_scrap_links` / `lookup_scrap_backlinks`。タグ起点なら `list_tags` / `lookup_tag_backlinks`。
- 根拠は `[[Title]]`（ctx 付きなら `[[Ctx/Title]]`）で示す。どの scrap を読んだか私が辿れるようにするため。
- 見つからなければ「wiki にない」と明示してから私に聞く。黙って一般論で埋めない。
- wiki は私の理解のスナップショットで、リポジトリの現状ではない。食い違ったらコードを正とし、食い違ったこと自体を報告する。
- MCP が繋がっていないセッションでは、wiki 本体が `~/dotfiles/wiki/scraps` 配下に markdown で置いてあるので Grep / Read で代用する。

## コードコメント

- 連続する1つのコメントブロックは**最大5行**。コード・設定ファイル・スクリプトを問わず一律で適用する。
- 5行に収まらないなら、コメントを削るかコード側を分かりやすくする。長い背景説明は README / ADR / PR 本文に書く。
- 「何をしているか」ではなく「なぜそうしたか」だけ書く。コードを読めば分かることは書かない。
- 差分の説明（`// 〜を追加`、`// 修正: 〜`）は書かない。それは commit message と PR の仕事。
- 既存のコメントは、その箇所自体を編集するとき以外は短縮しない。
